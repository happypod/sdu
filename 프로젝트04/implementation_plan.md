# 구현 계획 — 밝은 그라데이션 테마

## 목표

URL2QR 로고의 노란색을 기준으로 밝은 화면을 구성하고, 마우스 위치에 따라 그라데이션 색상과 중심점이 조금씩 바뀌도록 만든다.

## 화면 구성

- 배경: 밝은 노랑·살구·하늘색을 겹쳐 자연스럽게 섞는다.
- 헤더와 푸터: 배경이 비치는 밝은 표면으로 연결한다.
- 입력창: 흰색 표면과 따뜻한 테두리로 읽기 쉽게 표현한다.
- 확인 버튼: 로고와 연결되는 노란색 그라데이션을 사용한다.
- 제목: QR 부분에 진한 황금빛 포인트를 넣는다.
- QR 결과: 흰 바탕과 검은 코드로 스캔하기 좋은 대비를 유지한다.

## 커서 반응

1. 커서 좌표를 화면 너비와 높이에 대한 0–1 값으로 변환한다.
2. 좌우 위치로 노란 빛의 중심과 색상을, 상하 위치로 하늘색·살구색을 조정한다.
3. CSS 변수로 그라데이션의 위치와 색상을 바꾼다.
4. `requestAnimationFrame`과 시간 기반 보간으로 커서를 부드럽게 따라간다.
5. 목표 값에 도달하면 애니메이션 프레임 요청을 멈춘다.
6. 커서가 화면을 떠나면 기본 배경으로 돌아간다.

## 접근성과 사용 환경

- 모바일 터치 환경에서는 기본 그라데이션을 표시한다.
- 운영체제/브라우저의 `prefers-reduced-motion` 설정을 존중한다.
- 탭이 숨겨지거나 창이 포커스를 잃으면 프레임 요청을 취소하고 기본값으로 되돌린다.
- 배경 레이어는 클릭과 스크린리더 탐색을 방해하지 않는다.

## 변경 파일

- `index.html`: 장식용 배경 레이어와 제목 포인트.
- `styles.css`: 밝은 테마와 다중 그라데이션.
- `app.js`: 커서 좌표, 보간, 환경별 동작 제어.
- `README.md`: 새 테마와 실행 방법 안내.

## 검증 계획

- 커서를 다른 위치로 움직였을 때 위치·색상·실제 배경 픽셀이 바뀌는지 확인한다.
- 커서를 멈춘 뒤 값이 안정되는지 확인한다.
- 모바일과 동작 줄이기 설정에서 반응을 멈추는지 확인한다.
- 입력창 이동, QR 생성, 실제 JPG 다운로드 및 QR 판독을 다시 확인한다.
- 문법 오류, 브라우저 오류, 불필요한 외부 요청을 확인한다.
